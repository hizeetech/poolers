Django renders this page (HTTP 400) from django.contrib.admin.options.ModelAdmin.changelist_view when the querystring contains BOTH the "e" error flag AND an unrecognised lookup parameter. The upstream template does `{% extends "admin/base_site.html" %}`. With Jazzmin installed that parent chain ends in admin/base.html, which calls `{% sidebar_status request %}`. Django builds this particular response with a bare SimpleTemplateResponse that carries no request, so `request` is absent from the context and the tag receives the empty-string fallback -- raising `AttributeError: 'str' object has no attribute 'COOKIES'` and turning a harmless 400 into a 500. This override is deliberately standalone: it extends nothing and reads no context variable, so it always renders. {% endcomment %} {% translate 'Invalid page parameters' %}
